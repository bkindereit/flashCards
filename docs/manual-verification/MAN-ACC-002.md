# MAN-ACC-002 — Screen-Reader Verification Procedure

## Procedure Steps
Use one documented screen-reader/browser pairing supported by the verification environment (e.g., VoiceOver + Safari/Chrome or NVDA + Firefox/Chrome).

1. Read headings, regions, controls, and status on sign-in and deck views.
2. Trigger invalid CSV, authentication, offline, and grade errors.
3. Run one study card through reveal and both grade-state announcements.
4. Run diagnostics and inspect component statuses.

## Acceptance Criteria
- Controls have meaningful accessible names and states.
- Question, answer, errors, pending state, and status changes are announced.
- Hidden answer content is never exposed before user reveal.
